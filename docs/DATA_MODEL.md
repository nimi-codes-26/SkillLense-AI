# Data Model

## Student Profile — The 9 Features

The canonical definition is `backend/app/schemas.py`'s `StudentProfile` Pydantic model. The
frontend's `frontend/src/constants/fields.js` must stay in sync with these names and ranges.

| Field | Range | Group (frontend) | Description |
|---|---|---|---|
| `cgpa` | 0–10 | Academic | Cumulative grade point average |
| `coding_skill` | 0–10 | Technical | Self-rated coding ability |
| `dsa_skill` | 0–10 | Technical | Self-rated data structures & algorithms ability |
| `math_aptitude` | 0–10 | Technical | Self-rated math aptitude |
| `communication_skill` | 0–10 | Professional | Self-rated communication ability |
| `security_knowledge` | 0–10 | Technical | Self-rated security knowledge |
| `projects_count` | 0–10 | Professional | Number of projects completed |
| `internships_count` | 0–5 | Professional | Number of internships completed |
| `certifications_count` | 0–5 | Professional | Number of certifications earned |

All 9 fields are required on every request to `/predict-skill-category` and
`/career-alignment`; Pydantic enforces the numeric bounds above (`Field(..., ge=..., le=...)`)
and rejects out-of-range or missing values with a 422 response.

## Dataset (`ml/`)

- **Source**: synthetic, generated by `ml/generate_synthetic_data.py`.
- **Size**: 300 students, `RANDOM_SEED = 42`.
- **Method**: each student is assigned one of 5 hand-defined archetypes
  (`high_allround`, `technical_strong_soft_weak`, `average_balanced`, `developing`,
  `security_focused`), then each of the 9 features is sampled from a normal distribution
  centered on that archetype's mean value with noise (`NOISE_STD = 1.2`), clipped to valid
  range, and rounded.
- **Files**:
  - `ml/data/raw/student_data.csv` — the dataset actually used for all modeling (9 feature
    columns, no label, no archetype column).
  - `ml/data/raw/generation_reference.csv` — records which archetype generated each row, kept
    only for the author's own post-hoc sanity-checking. **Must never be used as a feature or
    training/evaluation target.**
  - `ml/data/raw/DATASET_NOTES.md` — full generation methodology, column descriptions, and
    stated limitations.
  - `ml/data/processed/` — exists as a directory (with a `.gitkeep` placeholder) but no
    processed/split files are persisted there; the train/test split and scaling happen
    in-memory within the notebooks.
- **Limitations**: synthetic, not real student data; designed to be replaceable later by real
  survey data without changing column names, ranges, or downstream code (per
  `DATASET_NOTES.md`).

## Skill Category (ML Output)

Four categories, produced as described in [ML_METHODOLOGY.md](ML_METHODOLOGY.md):

- Needs Improvement
- Strong Technical
- Balanced
- Strong Overall

Defined in `ml/models/cluster_category_mapping.json` (cluster index → category name) and
`ml/models/classifier_info.json` (`target_categories`). The classifier outputs these strings
directly.

## Career Roles (Rule-Based Alignment Input)

Defined in `backend/app/career_roles.py` — fixed, illustrative requirement profiles, **not**
derived from data or any hiring dataset (see explicit docstring in that file and
[ML_METHODOLOGY.md](ML_METHODOLOGY.md)). Each role has a `role` name, a `description`, and a
`requirements` dict giving a required level for all 9 features.

| Role | cgpa | coding | dsa | math | comm. | security | projects | internships | certs |
|---|---|---|---|---|---|---|---|---|---|
| Software Developer | 6.5 | 8 | 8 | 6 | 6 | 3 | 5 | 2 | 1 |
| Data Analyst | 6.5 | 6 | 5 | 8 | 7 | 2 | 4 | 1 | 2 |
| ML Engineer | 7 | 8 | 7 | 9 | 6 | 2 | 5 | 2 | 2 |
| Web Developer | 6 | 7 | 5 | 5 | 6 | 4 | 6 | 1 | 1 |
| Cybersecurity Analyst | 6.5 | 6 | 4 | 5 | 6 | 9 | 4 | 1 | 3 |

Notable per-role emphasis (from each role's `description`): Software Developer =
coding/DSA generalist; Data Analyst = math + communication leaning; ML Engineer = highest
math-aptitude requirement of all 5 roles; Web Developer = highest project-count requirement;
Cybersecurity Analyst = by far the highest security-knowledge requirement and the highest
certifications requirement.

## Career Alignment Formula

Implemented in `backend/app/alignment_service.py`:

```
gap(feature)            = max(0, required[feature] - actual[feature])
total_gap(role)         = sum of gap(feature) over all 9 features
max_possible_gap(role)  = sum of required[feature] over all 9 features
alignment_score(role)   = 100 * (1 - total_gap(role) / max_possible_gap(role))
```

- `skill_gaps` for a role includes only features where `actual < required`, sorted by gap
  size, largest first.
- The best match is the role with the highest `alignment_score`; ties are broken by the order
  roles appear in `CAREER_ROLES` (Python's `max()` returns the first maximal element).
- This formula is independently verified against hand-calculated values in
  `backend/test_alignment.py` (see the `manual_verification()` function for a fully worked
  example).

## Career Path Taxonomy (Frontend)

Defined in `frontend/src/constants/careerPaths.js` as `CAREER_PATH_CATEGORIES`, a browsable
grouping shown in the Career Alignment / Home career-path explorer. Each entry maps a path
name to a `roleKey`: either the name of a live backend role (from the table above) or `null`
for a path that is shown in the UI but not yet backed by a real backend role ("coming next").

| Category | Path | Backed by live role? |
|---|---|---|
| Technology | Software Engineering | Software Developer |
| Technology | Web Development | Web Developer |
| Technology | Data & AI | ML Engineer |
| Technology | Cybersecurity | Cybersecurity Analyst |
| Technology | Cloud & DevOps | No (`null`) |
| Data & Analytics | Data Analyst | Data Analyst |
| Data & Analytics | Business Analytics | No (`null`) |
| Product & Design | UI/UX | No (`null`) |
| Product & Design | Product Management | No (`null`) |

See [CURRENT_STATE.md](CURRENT_STATE.md) for the implication of the `null`-mapped paths
(they render as non-functional placeholders in the explorer).
